RBMK Monitor - Changelog
========================

18.4
- New terminal command: `void`. Prints the core's positive void coefficient
  (RBMK's defining flaw): void fraction = steam / (steam + boiler water),
  scaled by how far the rods are withdrawn (0.45x fully inserted, 1.00x fully
  out). Reactivity above 18% is flagged as self-accelerating.
  It is an estimate from the same snapshot `status` uses, not a direct read.
- Version bumped to 18.4 (Tags.VERSION + project.version together).

18.3
- Network handshake relaxed back to the Forge default: a peer that does NOT
  have this mod is now ACCEPTED (onNetworkCheck returns true), so vanilla
  servers and clients without the mod no longer get "mod rejections". A peer
  that HAS the mod but with a different version is still rejected - the
  packet table stays version-locked (protocol 11).
  /rbmkcompat now prints "no RBMK-Monitor on remote (accepted)" for that case.
- New NetGuard (network/NetGuard.java): all 55 outgoing packet call sites now
  go through a null check + try-catch Throwable, and all 23
  IMessageHandler#onMessage bodies are wrapped the same way. A failed send or
  a packet that arrives in an unexpected state is logged once per packet type
  and dropped; it can no longer break the caller's tick, the network thread
  or a dedicated server.
- Version bumped to 18.3; Tags.VERSION and project.version moved together so
  verifyModMetadata stays green.

18.2
- Steam-explosion scenery rebuilt to follow HBM's real event: the top lid
  launches, 140 debris pieces rain down over 3 seconds, 32 surface craters
  are stamped, and residual fires and smoke columns linger.
- Threshold watch chain: `watch <metric> <op> <value> do scram|alarm|audit`
  in the terminal. Rules persist to rbmk_watch.json, fire at most once per
  200 ticks, and the whole chain is gated behind the badge approval flow
  (unanimous admins to enable, any one admin to disable).
- Custom-page layout editor: instruments, curves and text blocks (up to 12)
  can be placed and scaled freely; layouts export and import through the
  clipboard.
- Settings center on every display screen (sneak + double right-click):
  brightness 40-100, four phosphor themes, curve compare mode with an
  optional log axis, and one-click run reports (CSV/HTML).
- Media screens can play slideshows: `media play slides@[3-60]` cycles
  rbmk_media/slides/.
- Black box: rbmk_history/index.txt, plus /rbmkhistory merge <x> <y> <z>.
- Audit log rotation now keeps multiple generations (4 MB each, .1/.2/.3).
- Network protocol 9 -> 10: packets 17/18/20 changed format. 18.2 cannot
  talk to any other version; both sides must run 18.2.

18.1
- Curve history is recorded from the moment a screen is placed (or its
  chunk loads), not only while a player is watching the graph page with the
  screen powered on. Export and replay therefore start at placement time.
- An unpowered real screen freezes its sampler instead of clearing history;
  it renders a black "no power - history paused" panel with a resume hint
  and continues from the same point once power returns.

18.0
- Curve history black box: per-screen history persists across chunk unloads,
  world reloads and game restarts under rbmk_history/<dim>_<x>_<y>_<z>.
  Writes use temp file + atomic rename; chunk unload flushes immediately,
  the rest batched every 15 seconds, and world unload flushes everything.
- Export time ranges: the double-click panel cycles all/60 s/300 s and
  /rbmkexport csv|png [seconds] accepts the same window; file names carry a
  _60s/_300s suffix.
- Cycle screen (rbmk_cycle_screen): overlay -> heatmap -> graph, 3 s per
  page by default.
- Terminal pipeline filters (`status | heat > 800`, aliases, chaining, 10 s
  validity) and macros (`macro set/run/list/del`, depth <= 3).
- Screen scans for alarm-light binding, the patrol hub, the aggregate hub
  and /rbmktrace now share one loaded-chunk-only helper; they never load
  terrain.
- Network protocol 8 -> 9 (packet formats unchanged; the major version
  forces both sides to align).

17.9
- Map view on the patrol hub. The patrol GUI gains a second button
  ("Map view"); when on, the list + detail panels are replaced by a
  2x2 grid of thumbnails, one per bound screen. Each cell carries a
  state-colored frame (red while hacked/critical, yellow on warnings,
  grey unpowered, green healthy), the screen type, a mini bar chart of
  the core-temperature channel (same client-sampled history the detail
  panel uses - zero new packets), and one status/readout line (alert
  reason wins over numbers). Click a cell to select it; auto-rotate and
  "jump to whoever alerts" run unchanged in both modes.
- Compat probe: /rbmkcompat (permission level 0, read-only). One
  command answers every question the first minute of troubleshooting
  asks: local version and network protocol (new ModNetwork.PROTOCOL
  constant, 8 since the 17.8 packet slimming), running side, MC/Forge/
  Java versions, the 22-packet registration table, security switch
  snapshot (hack master, normal-player hack, global revoke epoch),
  data-file locations, shader-pack / SSS pipeline state (client side),
  OptiFine presence, a keyword scan for potentially overlapping
  screen/hud mods, and the last handshake's remote version with the
  verdict. The handshake recorder (@NetworkCheckHandler on the mod
  class) replicates Forge's default check semantics exactly - nothing
  loosened, nothing tightened - it only records: remote versions land
  in ProtocolGuard, refusals are explained precisely (remote v17.7 vs
  local v17.9, "update the remote") into the console log and the audit
  trail as NET_REJECT, instead of the opaque FML "mod rejections"
  screen being the only trace.
- Hack gameplay phase 2: reverse tracing. Every successful hack now
  stamps the screen's NBT with the intruder's name and the world time
  (Hacker / HackTime / HackFixed); repairing the screen does NOT wipe
  the evidence - the trace is a forensics record, not the state. New
  command /rbmktrace [player] (permission level 2): with no arguments
  it scans the loaded chunks within 64 blocks for screens carrying
  traces and lists position, live/repaired state, intruder and how
  long ago; with a player name it walks the loaded chunks of the
  current dimension and lists every screen that player hacked. Both
  modes audit themselves (TRACE). Tile side: setHacked(boolean,String)
  overload, collectScreens() static (loaded chunks only, never loads
  terrain), legacy saves read as "no trace" and old worlds load
  unchanged.
- Reactor aggregate hub: rbmk_aggregate, the flagship "central control
  room" view. A 1x1 block binding up to 6 screens (same scan-bind flow
  as the patrol hub, radius 24); screens are grouped by the console
  they read (one console = one reactor; screens without a console
  stand alone) and the GUI shows the ranking: a summary bar (reactor
  count / online / total flux / hottest core), then one row per
  reactor sorted by core temperature with melt-downs pinned to the
  top - coordinates, a temperature bar against the 1000 C reference,
  flux, alert word, per-reactor screen count. Grouping is computed
  server-side (the screen's consolePos is server-only) and delivered
  by MessageAggregateSync (discriminator 22, 6 ints per screen);
  live readings still come from each screen's own client sync, so the
  hub forwards nothing and offline screens say so. Meltdown rows tint
  red, the hottest healthy row gets a green wash. Recipe: 2 iron +
  2 redstone + gold ingot + glass pane + patrol hub.
- History export: /rbmkexport <csv|png>, a client-side chat command
  (registered in ClientCommandHandler, dedicated servers never load
  it). Aim at any screen in reach (ray-trace up to 32 blocks) and it
  exports that screen's client-sampled GraphHistory - the exact data
  the graph screen draws. CSV: one row per sample, six channels plus
  the per-sample alert level, data-loss gaps left empty, Excel-ready.
  PNG: a stacked long chart, one auto-ranged grid panel per channel
  with a colored polyline and peak label, plus an alert ribbon at the
  bottom (L1 yellow / L2 red) - post it in the group chat and the
  incident reads at a glance. Files land in <game dir>/rbmk_export/
  named by screen coords and a timestamp, never overwriting an older
  export. Replay is a viewing mode: the export always covers the full
  sampled window.
- Export settings panel (GUI path): sneak + double right-click on a
  screen (two clicks on the same screen within 700 ms) opens a client
  side "Export Settings - Graph History" panel with the screen coords,
  a live sample-count preview, a CSV/PNG format toggle and an
  "Export graph history" button; success prints the saved path in chat
  and closes the panel. The panel lives entirely on the client (no
  container, no packet, id-free); it is opened from ScreenMultiblock's
  client branch and never hijacks sneak-clicks that carry a tuner /
  config card / recipe card / siren horn / remote - those item
  branches run first. Each click of the pair still walks the normal
  server power-toggle path (net state unchanged, action-bar notices
  only). The command and the panel share one exporter implementation
  (RbmkExporter); the <game dir>/rbmk_export/ directory is created by
  the game at runtime (mkdirs, idempotent) - no manual setup needed.
- Self-review fixes (same release): /rbmkexport's aim ray now resolves
  the controller screen through findController when the crosshair hits
  a visible multiblock panel (part blocks carry no TileEntity, so the
  command used to report "not aiming at a screen" while pointing
  straight at one - the double-click panel already resolved this way);
  the exporter appends _1/_2... to the file name when two exports land
  within the same second instead of silently overwriting ("never
  overwrites" now actually holds); the ModNetwork discriminator table
  was corrected against the real registrations (SirenTune occupies
  ids 6/7, not 5; the registry holds 23 packets, ids 0..22 - the
  in-game /rbmkcompat numbers were already correct).
- Alarm light auto-colouring is now an explicit panel option ("Auto-colour:
  ON/OFF", relabelled from "Link"): ON = the lamp scans for the nearest
  display within 16 blocks and recolours by alert level (unchanged
  behaviour); OFF = the player colours it themselves - and now this
  actually holds. The player's manual colour / spin / switch are
  snapshotted into the save NBT (MColor/MRpm/MOn) when auto-colouring
  is turned on and restored when it is turned off, via the panel button
  or the remote (sneak + right-click). Previously poll() overwrote the
  live config with alert values, so unlinking left the lamp stuck on
  the last alert colour. The AUTO_OFF panel packet no longer applies
  its slider values (they still show alert colours while linked) on
  top of the restored manual settings. The snapshot lives in the save
  NBT only, not in the update tag; pre-17.9 linked lamps without a
  snapshot keep the old keep-current-colour behaviour.
- Alarm light trigger modes re-labelled around "does it accept redstone"
  and extended with a fifth mode TRIGGER_ALWAYS (4): the lamp is lit
  unconditionally - redstone level and the manual switch take no part,
  both right-click gestures only open the panel (there is no "switch"
  action in this mode), the panel's lamp button greys out with an
  "always lit" caption, and a hint line explains it. Button labels now
  read: no redstone (click) / no redstone (sneak) / redstone (powered
  = lit) / redstone + manual / wireless: always lit. The trigger value
  grows from 2 to 3 bits in MessageAlarmLight and the NBT clamp accepts
  0..4 (out-of-range still falls back to TRIGGER_ANY); old clients only
  ever send 0..3, and mode 4 read back by an old build degrades to
  click mode (mask &3) without disconnecting. The lamp button stays
  locked in redstone mode as before.
- Sixth trigger mode TRIGGER_OFF (5), mirroring always-lit: the lamp is
  unconditionally dark, redstone and the manual switch take no part,
  both gestures only open the panel. Still inside the 3-bit trigger
  field, so the packet format is unchanged. Labels now read: no
  redstone (click) / no redstone (sneak) / redstone (powered = lit) /
  redstone + manual / wireless: always lit / off: always dark.
- Panel bottom row rebuilt: "Apply" saves as before, "Cancel" restores
  the whole panel state as it was when the panel was FIRST opened
  (snapshot taken on first initGui, not on window resize). Because
  every click already sent a packet, cancel sends reverse packets:
  first the auto-link difference (AUTO_ON/AUTO_OFF, computed BEFORE
  the local snapshot restore which would erase the diff), then a
  AUTO_KEEP packet carrying the snapshot colour/rpm/switch/spot/trigger
  so the server ends exactly at the opening state (AUTO_OFF alone
  would restore the bind-time snapshot, not the panel-open one).
- Export/Import settings buttons (native file dialog, client only):
  export writes a UTF-8 key=value text (rbmk-alarm-settings=v1 header;
  colour as #RRGGBB, rpm 0..120, on/spot/trigger by name, auto flag)
  anywhere on disk via a save dialog, defaulting to the game directory
  with a position-stamped file name; import opens the dialog, parses
  strictly (header version checked, unknown keys ignored for forward
  compatibility, any invalid value rejects the WHOLE file with a line
  number - never a half-applied state) and sends the same two-phase
  packets. The dialog is modal: the game frame freezes while it is
  open, which is the pragmatic 1.12.2 answer to "no built-in file
  picker".
- Hardening during self-review: MessageAggregateSync and the 17.7-era
  MessagePatrolSync both clamp their element count to [0, slots] -
  a crafted/cross-version packet with a negative count would have
  thrown IllegalArgumentException inside the netty thread (instant
  kick) when constructing the ArrayList. Also: the compat probe now
  reports 23 packets (ids 0..22) after the aggregate packet joined
  the table; version stays 17.9 - these features ship inside the same
  build as the rest of the 17.9 banner.

17.8
- Version unified to 17.8. This banner covers the release previously
  drafted as 17.7. This release merges what used to be tracked as 17.7
  (permission wrap-up, audit log, replay, patrol) and 17.8 (recipe card,
  issuer protection, GUI hub, packet slimming, handbook vol. III) into
  a single banner.
- Badge revocation command: /rbmkrevoke <player|all> (permission level
  2). Cards are entity credentials and deliberately not player-bound,
  but the issuer knows who it issued to: issued cards now carry a
  Holder stamp and the revocation epoch of that holder at issue time.
  Revoking a name bumps that holder's epoch; "all" bumps the global
  epoch and also kills legacy cards without a holder stamp. A card
  whose epoch lags the registry is invalid the moment it is shown -
  wherever it is. Revocation state persists to rbmk_revoke.dat in the
  save dir (epoch rollback would resurrect revoked cards, so write
  failures are logged loudly). Fix during self-review: issued-card
  epoch stamps now take max(global, holder) - previously a badge
  issued after "rbmkrevoke all" carried only the holder epoch (0) and
  was instantly dead, bricking the issuer until the global epoch was
  mirrored onto every new card. Every revoke is audited (BADGE_REVOKE)
  and the online target is notified in chat. The tuner's denial now
  distinguishes "no badge" / "used up" / "revoked".
- Alert markers on the graph screen. The client-sampled history now
  records the alert level alongside the six channels; the graph panels
  draw a translucent vertical line at every L1 sample (yellow) and L2
  (red), so consecutive alerting samples read as a band whose width is
  the duration. Markers share the replay window: scrubbing back shows
  them under the curves at the same moments. Zero packets: the level
  rides the existing canvas sample.
- Audit query filtering: /rbmkaudit takes grep-style keywords - every
  non-numeric argument (max 3) must appear in a line for it to match,
  matched case-insensitively against the full formatted line (player
  names, actions and details all participate). Numeric argument stays
  the count, capped at 200. /rbmkaudit Steve REVOKE 10 = Steve's last
  10 revocation entries. Tab completion offers player names.
- Bilingual handbooks. All three volumes carry a full English page set
  (PAGES_EN, page-for-page with the Chinese originals, still hardcoded
  safe files - no .lang for book pages, same reasoning as before). The
  client-side NBT self-heal now also compares a Lang stamp against the
  client language and re-prints the book in the reader's language on
  first open; server-side /give and recipes keep producing the Chinese
  default. Vol. III chapter 4 documents /rbmkaudit filtering and
  /rbmkrevoke; firmware banners updated to 17.7 in all volumes.
- Permission system wrap-up, part 1: audit log. Every privileged act now
  leaves a trace: card issuance (per batch, with failure counts), badge
  revocation, tuner adjustments by card holders (screen, tier, card-holder
  flag), hack request / vote / veto / outcome, screens hacked and screens
  repaired, security-code passes, and an issuer broken while holding blank
  cards. Written to rbmk_audit.log in the server data directory, append-only
  with a single 4 MB .old rotation; every line flushed immediately so a
  crash cannot eat the last entry; failures degrade to one console warning
  instead of throwing into the caller. /rbmkaudit [n] (permission level 2)
  prints the last n entries from an in-memory tail so operators do not have
  to shell into the box for a quick "who did this".
- Permission system wrap-up, part 2: the audit trail deliberately does NOT
  cover badge issue-from-creative or chat-visible broadcasts - what it does
  cover is exactly the actions that change rights or fake data, keyed by
  player name and coordinates, greppable with plain text tools.
- History replay on the graph screen. Scroll the mouse wheel while looking
  at a graph display (powered): up scrolls back into the recorded window
  (1 second per notch, the same client-sampled history the live chart uses),
  down walks forward, reaching 0 returns to live. A yellow banner shows
  "REPLAY t-XXs" while scrubbing and the three panels render history up to
  the scrub point, end-value labels included. No packets, no GUI: the
  pointer lives in the client canvas next to the history it points into,
  the server never hears about it, and the wheel event is consumed so the
  hotbar does not page. Live sampling continues underneath, so replay is
  strictly "rewind what was recorded", not a pause.
- Screen patrol hub (rbmk_patrol), a 1x1 block: the duty officer's seat.
  Sneak+right-click scans up to SCAN_RADIUS=24 blocks and binds the nearest
  unbound screens (all monitor-screen tiles count) into 4 slots, saved to
  NBT. Right-click opens a read-only panel: one row per bound screen with
  type, coordinates, alert level (colored) and heat/flux readouts; clicking
  a row selects it and shows a detail pane with status line plus a heat
  history mini-chart drawn from that screen's own client-side canvas
  history - the same data the graph screen plots, no extra sync. Auto
  rotate mode switches the selection every 5 s and jumps instantly to the
  worst alerting screen ("whoever alarms gets watched"). Bound lists reach
  the client through a dedicated packet (21) because coordinates do not fit
  window properties; removed screens are pruned client-side, silently, and
  the server slots are freed on the next scan. The hub itself carries no
  gate: patrolling is viewing, not a credential.
- New item: Screen Recipe Card (rbmk_recipe_card). Where the config card
  moves 15 tuning keys, this one takes a blacklist-based snapshot of an
  entire screen: everything except the "field state" (power, energy,
  run ticks, alert cache, messages, security code, owner, tilt, media
  playback state, PPT slide position) and the TileEntity identity keys
  (id/x/y/z/ForgeData) goes into the card. Custom-screen watch slot
  lists, media file/volume, PPT picture mode all travel with it.
  Sneak+right-click a screen to snapshot, right-click to paste (paste
  overlays only keys the card holds, so cross-type pastes are safe -
  each tile reads the keys it knows and ignores the rest), sneak+right-
  click air to clear. Paste is audit-logged (RECIPE_PASTE). Recipe:
  config card + 2 paper + gold ingot.
- Issuer griefing protection, three gates. Placement records the placer
  as owner (persisted in NBT as OwnerUUID/OwnerName). removedByPlayer
  now refuses (returns false, block stays) when the breaker is neither
  owner, admin (level 2 / single-player host) nor creative, and logs
  ISSUER_BREAK_DENIED to the audit trail. onBlockExploded is
  intentionally empty: the counter is immune to all explosions. The
  blank cards stay in the drawer, period.
- GUI unified safe rendering. GuiDraw is now the single drawing hub for
  mod-owned GUIs: rect() auto-fills a missing alpha channel (vanilla
  Gui.drawRect silently draws nothing without it), hline()/vline(),
  text()/textCentered() normalize colors too, and safe() translates a
  key with a readable fallback instead of leaking the raw key onto the
  panel when a translation is missing. GuiRbmkPatrol (overview, rows,
  detail panel, mini histogram) migrated fully as the reference
  implementation; existing GuiDraw callers keep their semantics.
- Network slimming. The per-screen sync packet (highest frequency in
  the mod) loses 52 bytes: the ten snapshot doubles now travel as
  floats (display precision), and tilt/alertLevel/rsPower/
  realPowerState travel as single bytes. Registration table is now one
  place: the four messages (ids 8..11) that lived in
  RbmkMonitorMod.preInit moved into ModNetwork.init, ids unchanged.
  Wire format changed, so old clients cannot join new servers (and
  vice versa) - same rule as any content update.
- New item: Administrator Handbook Vol. III (rbmk_manual_vol3), same
  read-only written-book construction as vols I/II (three siblings, no
  shared base class on purpose). Eleven chapters cover the permission
  system end to end: issuer procedure, badge semantics, audit log and
  /rbmkaudit, patrol control, graph replay wheel, hack approval flow,
  card vs template division of labor, the griefing checklist and
  troubleshooting. Recipe: book + black dye + 2 paper + iron ingot.
- Crafting recipes are now printed inside the handbooks. Vol. I gains
  three appendix pages (screens / terminal family / alarm family) and
  a proper closing page (18 pages total); Vol. III gains three appendix
  pages (permission items / patrol items / the handbooks themselves,
  15 pages total). Every entry is transcribed from the actual recipe
  JSON in the jar, shaped grids written as 铁=iron shorthand, not
  invented. Tooltips state the new page counts.

17.6
- The cone implementation is now four explicit choices instead of one cycling
  button: Auto / FBO / Cone / Glow. Per lamp, saved to NBT, applied on click
  without closing the panel. Auto follows alarm.sssLighting as before; FBO and
  Cone are the two old paths made selectable directly. The button ids do not
  line up with the SPOT_ values (FBO is id 11 and SPOT_SSS is 2), because the
  buttons are ordered the way a player reads them, not the way the constants
  happen to be declared.
- New fourth path: Glow. The lamp gets a camera-facing halo at the lens plus 6
  billboards marching down each beam, each larger and fainter than the last,
  all cut from rbmk_alarm_light_glow.png - a 64x64 pure-white radial fade that
  was already in the jar. Vertex colour tints it, so the halo is any colour
  the lamp is. Beam length comes from the outer ring of the ray trace the
  geometry path already computed, averaged, so the column stops at the wall
  instead of poking through it. That is an approximation, not per-puff
  occlusion; anyone who wants strict occlusion should pick Cone.
- Glow is the only path that survives a shader pack, and that is the whole
  reason it exists. It is POSITION_TEX_COLOR with real UVs, so the pack treats
  it as ordinary world geometry and samples the sheet correctly. The other two
  are textureless POSITION_COLOR (Cone) or a self-written program (FBO), both
  which come out as black haze under a pack.
- Shader packs, revised: AlarmLightVolume no longer bails out of the entire
  frame. It keeps drawing Glow and skips everything else (see draws()). Manual
  FBO and Cone lamps draw nothing under a pack; Auto picks Glow on its own
  (final behavior, see the Auto entry below). Making Cone work under a
  pack would mean feeding the pack's pipeline our own white sheet and touching
  the shader path, which is exactly the kind of change that turns a cosmetic
  glitch into a black screen. Deliberately not done.
- The pack detection was broken from the day it was written: it reflected
  Class.forName("Config") without the net.optifine prefix, threw
  ClassNotFoundException on every call, and the catch turned that into "no
  pack". The fallback branch it guarded never ran once in its life. It now
  delegates to the detector DepthDebugPass already had
  (Shaders.shaderPackLoaded, then Config.isShaders, cached), so SSS and the
  geometry path can no longer disagree about whether a pack is on.
- The old textureless fallback decal is gone and stays gone. It was an overlay
  billboard in the same POSITION_COLOR format as the cones, with the same
  missing UVs, so it sampled gtexture (0,0) and drew a black patch -
  worse than nothing. Glow is not that idea coming back: Glow carries real UVs
  and a real texture, which is the difference between a visible halo and black
  smudge.
- Fixed GL state leaking out of AlarmLightVolume. Its finally block reset
  blend, cull, texture, lighting, blend function and colour to hardcoded
  vanilla defaults instead of restoring what it found on entry. Vanilla happens
  to end the world pass in exactly those states, so it looked fine; any pass
  queued behind us (mod particles, highlight/wireframe renderers) lost its own
  state and rendered wrong. Cull, lighting, texturing, the blend flag and the
  depth mask are snapshotted on entry now and restored on the way out. The
  blend function is the one exception and still goes back to the vanilla
  default: GL reuses the same enum values for source and destination factors
  (770 is SRC_ALPHA in one slot and DST_ALPHA in the other), so an int cannot
  be mapped back to the GlStateManager enum without guessing, and guessing
  wrong is worse than a sane default.
- That snapshot is skipped entirely when no alarm light is within range. The
  five glIsEnabled / glGetBoolean calls stall the pipeline, and there is no
  reason to pay for them on a frame that draws nothing.
- DepthDebugPass no longer forces glUseProgram(0) on exit; it restores
  whichever program was bound beforehand. Same class of bug - a post-processing
  mod that had bound its shader earlier in the frame was kicked back to fixed
  function.
- Replaced the rotating alarm light with the original jiezhimod implementation
  instead of a lookalike. The block, the tile entity and the renderer are the
  upstream ones, plus a new com.jiezhirbmkmod.alarm package holding the config,
  the signal and the rule classes, so future upstream changes can be diffed
  against the source project.
- The lamp body is drawn as real geometry: 48-sided cylinders for the base, the
  bulb and the glass dome, plus the two opposed reflector plates that actually
  spin. No texture is involved, which is the only way a 16x16 sheet could ever
  produce a round dome without a jagged rim.
- The inventory icon, the in-hand model and the dropped item are the upstream
  textured cube again: block/cube_all with a 16x16 lens sheet (dark ring, red
  centre). The three json files (blockstates, block model, item model) are
  literal copies of the upstream ones - the only lines that differ are the
  namespace and the block name, so the indentation, the key order and all
  twelve variants stay identical to the source.
- Six-way mounting. FACING is the direction the lens points at, so a lamp
  clicked onto a ceiling hangs down, one clicked onto a wall looks out of that
  wall, and a floor lamp behaves exactly as it always did. The collision box
  and the TESR follow the same rotation.
- Per-position phase. The head angle is offset by a hash of the block
  coordinates (xorshift plus a multiply mix), so a row of lamps and a column of
  lamps both sweep out of step. The obvious x*A^y*B^z*C hash gave a constant 23
  degree step along a vertical column and a constant -67 along a row, which
  read as synchronous rather than random; both axes now spread over the full
  0-359.
- Dye still repaints a lamp straight from the hand, without opening the GUI.
  While the lamp is linked the dye is refused and the reason is printed in
  chat, rather than being silently swallowed.
- Sneak + right-click opens the control panel, which replaces the old
  colour-only editor: RGB sliders, spin speed, on/off and an alert-link toggle,
  plus a light cone switch and a trigger button, all in one screen.
- Alert linking is a switch now, not a one-shot remote trick. Opening it binds
  the nearest display within 16 blocks, closing it releases the lamp: yellow at
  10 rpm, orange at 30, red at 90, with the thresholds read from that screen's
  own alert policy, so the lamp turns yellow on the same tick the screen does.
  The remote still works as the shortcut - sneak + right-click a lamp with it
  in hand and it binds the nearest screen directly.
- Only the four-level mapping was adapted, not invented. The original reads a
  DFC snapshot (melting point, detonator, laser parts); this mod has an RBMK
  snapshot (column heat, heat rate, flux, melt risk), so AlertRules takes the
  latter and keeps the original colour and rpm tables untouched.
- Colour, spin and on/off are greyed out while the lamp is linked, with the
  reason on the panel: those three are rewritten by the alert level every 10
  ticks, so letting them be dragged would only make the lamp jump back a second
  later.
- New trigger mode: right-click / sneak right-click / redstone / any. It
  decides which gesture switches the lamp, and the gesture it does not use
  opens the panel instead - two gestures cannot both mean one thing or the
  panel becomes unreachable. Clicks that the current mode does not claim are
  passed through to vanilla (return false) instead of being swallowed,
  otherwise you could never place a block against the lamp again.
- Redstone trigger is authoritative: powered = lit, unpowered = dark. It leaves
  the manual on/off latch untouched, so flipping back to right-click restores
  what you had set. Only lamps that actually use redstone poll the level (every
  5 ticks), as a fallback for pistons, /setblock and other mods that move power
  without sending a neighbour update; the right-click and sneak modes do not
  poll, do not mark the chunk dirty and do not re-light the block.
- Linked lamps ignore the trigger entirely - the alert level owns on/off - so a
  reactor alarm can never be switched off by a redstone line going low. The
  button is greyed out with the reason and the value is kept for when you
  unlink.
- Two lighting paths, switchable per lamp from the panel and effective on the
  click, no restart. The screen-space spotlight uses an FBO depth capture plus
  an embedded GLSL fullscreen pass: soft edges, occluded by walls, glass and
  modded machines. The polygon-cone fallback uses rayTraceBlocks and has hard
  edges but no GL requirements. AlarmSpotlights skips lamps marked GEOMETRY and
  AlarmLightVolume skips lamps marked SSS, so exactly one of them ever draws a
  given lamp.
- Three optical postures, classified from the lens axis: floor lamps sweep two
  opposed beams at 35/55 deg over 8 blocks, wall lamps run one full circle
  hugging the wall at 15/45 deg over 10 blocks, ceiling lamps shine straight
  down at 45/75 deg over 10 blocks. One classifier feeds both the beam maths
  and the shader, so the visible lamp and the lit spot cannot disagree.
- alarm.sssLighting in the config is only the default for the automatic
  setting. Added the sssAvailable safety net on top: if the shader fails to
  compile, a shader pack makes the pass step aside, the driver has no OpenGL
  3.0, or -Djiezhirbmk.debugDepth=false is set, every lamp falls back to the
  polygon cones. A lamp that is on with nothing lit is worse than a hard-edged
  beam.
- The fallback respects FACING too. It used to assume the lamp always stands on
  the floor, so a ceiling or wall lamp threw its beams out of the top of the
  block. Cone axis, beam count and rotation axis all come from the same
  LightType classifier the spotlight pass uses.
- The fallback traces start outside the lamp's own collision box. The lamp
  centre sits inside its AABB and rayTraceBlocks tests the block the ray starts
  in, so every ray hit the lamp itself and the cone collapsed to zero length -
  a lit lamp with no light. The start point is pushed to the first AABB face
  the ray crosses, capped at half the beam range.
- The fallback no longer computes its own head angle; it reads
  TileAlarmLight.angleDeg(), so the visible blades, the spotlight pass and the
  polygon cones all sweep together.
- The fallback's cone cache compares against the clamped radius. It used to
  compare the clamped value against the raw getRadius(), so any lamp with a
  radius below 1.0 rebuilt its cone every tick (576 raycasts per lamp per
  tick).
- Compatibility: the meta layout is unchanged (north 0, east 1, south 2, west
  3, up 4, down 5, bit 3 = lit), so a 17.5 world reloads with its lamps
  pointing the same way and lamps saved before the ON bit existed are re-lit on
  load. Old saves migrate Color / Speed / ManualEnabled / Powered into AColor /

  old right-click-or-redstone behaviour; defaulting to right-click would have

  its own axis changes nothing - it renders as a static outward cone rather
  than the sweeping wall circle the spotlight pass draws. That is deliberate:
  tilting the cone to fake the sweep would push half of it through the wall.

- Crash guard, from a player report of an instant black screen with a pack on.
  Two render entry points had no exception protection at all:
  AlarmLightVolume's per-lamp loop had try/finally but no catch, and
  RenderAlarmLight (the TESR) had none whatsoever - its state restore was
  written sequentially, so a mid-draw exception leaked GL state AND escaped
  up the pipeline. Any exception thrown past a RenderWorldLast handler or a
  TESR is FATAL in Forge: the client goes black on the spot. Shader packs make
  this likeliest - foreign programs own the geometry state, and anything from
  a Tessellator hiccup to a texture load can throw. Both entry points are now
  wrapped: the exception is logged once, the shared BufferBuilder is reset
  (without that, every later begin() anywhere throws IllegalStateException
  and one lamp's error becomes the whole frame's), and the TESR restore block
  moved into finally so GL state always comes back. Worst case is now one
  skipped lamp, not a dead client.

- New 250 ms "mid-high" tier. Screens store their tier in NBT, so two tiers that
  happen to share a millisecond value still come back as the tier the player picked.
- The screen sync packet now actually applies refreshMs on the client; before this
  the field was read and then dropped, so a rate change only showed up after the
  screen was reloaded.
- The refusal line uses TextComponentTranslation instead of the client-only I18n
  class, so it also resolves correctly on a dedicated server.
- Bumped the mod version to 17.4.

17.3
- Boot screen no longer shows empty boxes. The bundled font subset had only 544 glyphs,
  so the OS title (the "system" character) and the version line (the "kernel" character)
  were drawn as .notdef boxes. The subset is rebuilt from WenQuanYi Micro Hei with all of
  GB2312 level-1 plus every character the mod prints: 3897 glyphs, 774 KB.
- Text drawing now checks each character and draws anything the bundled font lacks with a
  same-size system font, so device names and future strings cannot turn into boxes.
- Fixed the boot percentage label. It was drawn at y=152 and its ink spans 146..152, so it
  covered the bottom edge of the progress bar and the last glyph hung 0.7 px past the bar
  end. The footer is now a caption row above the bar - self-test caption on the left,
  percentage on the right - both aligned to the bar's 12..244 span.

17.2
- Fixed the beam vanishing when the lamp itself sat outside the view cone: a 16 block
  cone can sweep across the screen while the lamp is off to the side, so the cull now
  only drops lights whose whole beam volume is behind the camera.
- Removed 576 Vec3d allocations per light per frame. Cone points rotate into reused
  float arrays, so a row of lamps no longer causes GC stutter while running.
- The shader path now draws both cones of the dual beam (one of them was skipped).
- Guarded a null placer (dispenser placement), a missing render view entity and a
  missing glow sprite.
- Clamped radius / speed / cone angle read from NBT so a corrupted save cannot ask
  for thousands of block rays per frame.
- Lamp list refresh 20 -> 10 ticks, newly placed lamps light up twice as fast.
- Added the mod logo (mcmod.info logoFile) for the Forge mod list.
- Boot and self-test screens now show the mod's own brand (RBMK MONITOR OS) instead
  of the original author's "Jiezhi OS". Brand strings live in ScreenLayout.OS_NAME /
  OS_TITLE, so renaming it later is a one-line change.
- Fixed the boot cursor: it was hard-coded at x=66 and drew on top of the title text.
  It now follows the measured text width, so a longer brand name still looks clean.
- Bumped the mod version to 17.2.
